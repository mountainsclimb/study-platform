## 2. 平台精选接入

### 2.1 读取适配层与可见性（`app/official.py`）

- 新增 [`app/official.py`](../app/official.py)：只读适配层，**不写广场表**，对外暴露
  `load_official_question` / `search_official` / `inspect_official` / `normalize_public_id` / `ref_of`。
  引用格式 `official:<public_id>`；`public_id` 为广场签发的 `plz-` + 20 位 hex（与内部自增 id 解耦）。
- 可见性（与 `app/plaza/db.py` 同一口径，**查询时判定、不做进程内缓存**）：仅
  `community_review`（社区待核验）/ `verified`（社区核验通过）/ `published`（平台精选）且 `public_id` 非空可读；
  `published` 还要求存在 `plaza_releases` 的 `status='active'` 发布指针。`draft/pending_initial/disputed/withdrawn/
  rejected/pending_release` 一律不可读；详情、列表、作答、工坊快照统一 **404**，不向前端回显任何受限正文。
- 投影与 `practice.load_question` 同形（`qid=official:<public_id>`、`source/source_label`、题干/选项/答案/解析/
  知识点/公开图），并携带 `public_id/official_status/status_label/review_status(_label)/published_version/
  published_at/featured/community_pending/notice/source_declaration/figure_notice`；答案/解析只在作答后解锁。
- 状态提示集中为中文常量（社区待核验 / 已核验 / 精选 / 撤回 / 争议 / 不可见）；`inspect_official()` 只返回可见性
  与状态摘要，供错题卡/复习队列在题目撤回后显示「内容已撤回/暂停展示」而**不回显正文**。
- 公开配图只输出广场公开衍生图地址 `/api/plaza/questions/{public_id}/images/{index}`（撤回/争议后 404），
  不泄露私有资产或存储路径。

### 2.2 统一引用与来源筛选

- [`app/question_ref.py`](../app/question_ref.py)：`SUPPORTED_SOURCES = (bank, app, official)`；`storage_key`
  对 official 保持 `official:<public_id>`；`QuestionRef.is_official()` / `source_label()` / `describe()` 等工具补全。
  解析仍为纯字符串工具，空 key/空白/超长等格式错误统一 422（读取层对不合法/不存在的 public_id 按 404 处理，
  不泄露格式）。
- [`app/practice.py`](../app/practice.py) `GET /api/questions` 新增 `source=bank|official|all`（`QUESTION_SOURCES`）：
  - `bank`（默认）：原有题库行为与结构不变（仍支持全部题库筛选与二次复习槽位）；
  - `official`：只应用 `subject`/`type`/`q`/分页，返回 `source/bank_total:0/official_total/notice`；
  - `all`：题库在前、精选在后，按合并偏移严格分页，返回 `bank_total/official_total`；
  - 非法 source **422**「来源筛选值无效，只支持 bank / official / all」；official 题型筛选同时接受工坊题型与
    练习题型（未知题型 422）；排序固定「精选 > 核验通过 > 待核验，再按更新时间」。
- 前端三处（练习/组卷/首页）用**非法 source 值**能力探测（旧后端会忽略未知参数并返回题库结果），探测不通过时
  整体隐藏来源控件，避免把默认题库伪装成「平台精选」。

### 2.3 作答 / 错题 / 复习 / 统计（`app/practice.py`）

- 接受 `official:` 的接口：`GET /api/questions/{qid:path}`、`GET /api/reveal`、`GET /api/attempts/history`、
  `POST /api/attempts`、`POST /api/mastery`、`POST /api/wrongbook`；写库键 `official:<public_id>`；
  幂等键 `official:<public_id>|<submission_id>`（`submission_ledger`，与 bank/app 互不吞并）。
- 判分与题库/个人题同一门槛：客观题（`SINGLE/MULTIPLE` 且选项与答案可解析）自动判分，`BLANK` 按文本规则，
  其余保留作答判 `pending`；撤回/争议后不可再作答（404）。
- 错题本/复习队列合并三类来源：错题卡带 `ref/source/source_label`；official 题撤回后降级为占位卡
  （`unavailable:true`、`withdrawn:true`、中文 `notice`），历史成绩仍可读；`GET /api/review/queue` 的 `items` /
  `pending_items` 同样包含 official 条目。
- `GET /api/stats` 新增 `official_attempts/official_practiced/official_wrong_count`；既有
  `attempts/practiced/wrong_count/accuracy/...` 语义不变；历史作答投影带 `ref/source/source_label`。
- 边界：题库侧 `POST /api/questions/{qid}/issues` 仍只服务只读题库题；平台精选题的纠错/举报走广场接口
  （§3.6）。`GET /api/bank-image` 只服务题库/个人题配图，精选题公开图走广场图接口。

### 2.4 工坊建卷快照与冻结练习（`app/paperlab/{papers,practice}.py`）

- [`papers.split_ref()`](../app/paperlab/papers.py) 接受 `official:public_id`：格式非法 **422**、不可见
  （未发布/撤回/争议）在快照时 **404**；`snapshot_official()` 冻结内容 + `public_id` + `published_version` +
  审核状态/来源声明 + 公开配图引用（`kind:'official'`、`public_asset_id`、`url`、`accessible`）。
- 整卷练习 `pl_attempt_items` 冻结语义不变：改题/删题/重排/删卷不影响已开始练习；精选题后续修订或撤回也
  **不改已冻结题面**、判分继续使用冻结参考答案；只有公开配图读取按广场当前状态实时授权（撤回/停用 404）。
- 整卷提交对 official 错题/待判题写入统一错题本（`wrong_questions.qid=official:<public_id>`），响应新增
  `official_bank_unlinked[]` / `official_wrong_added[]`，`notice` 汇总「题库/我的题库/平台精选」三类入账数。
- 卷面投影与导出/回看标注来源：`public_item` 增加 `source_label/public_id/review_status/review_status_label/
  published_version`；冻结配图路由（papers/attempts 两条）遇 official 图片转广场公开副本授权。
- 组卷候选池边界：AI 组卷（smart/knowledge/wrong/layered）仍只从题库与个人题取候选；official 通过手工选题
  （组卷页「平台精选/全部来源」页签）加入试题篮，建卷时由服务端按 `official:` 引用冻结快照。

### 2.5 与广场/质量运营的边界

- official 读取层**只读**：不修改投稿/发布/事件表；可见性完全由广场状态与活跃发布指针决定，因此
  「抽检 high 自动撤回」「编辑撤回」「作者撤回」「回滚」都会即时改变精选的检索/详情/作答可见性（§3.8）。
- 撤回后：列表/详情/作答/工坊**新建卷**不可再用；已建卷/已开始练习的题面与判分保持（冻结），错题/复习保留
  历史占位；历史作答行、掌握度、统计计数不删除。

## 3. 质量运营（通知 / 收藏 / 反馈 / 抽检 / 指标 / 回滚）

### 3.1 模块与路由（`/api/plaza` 44 条 = 原 25 + 新增 19）

- [`app/plaza/__init__.py`](../app/plaza/__init__.py) 在原有子路由基础上新增
  `notify` / `favorites` / `feedback` / `quality` / `metrics`，注册顺序把固定路径（`/me`、`/questions`、
  `/submissions/mine`、`/notifications`）放在动态段之前，避免被 `{id}` 抢占；总计 **44 条**（实测路由清单一致）。
- 新增 19 条：通知 2（`GET /notifications`、`POST /notifications/read`）；收藏 3（收藏/取消/我的收藏）；
  纠错举报申诉 10（用户提交 3、我的申诉 1、编辑端队列 3、处理动作 3）；抽检 2（队列/记录结论）；
  指标 1（`GET /admin/metrics`）；回滚 1（`POST /submissions/{id}/rollback`）。
- 所有写事务统一 `db.write_lock(con,"plaza-write")` + 显式主键；通知/事件与状态更新同事务；
  队列/抽检/指标/回滚使用 `service.require_plaza_role("editor")`（admin 直通），普通用户 403。

### 3.2 数据表与常量（`app/plaza/db.py`）

- 新增 6 张表（幂等 `CREATE TABLE IF NOT EXISTS`，广场表共 14 张）：
  - `plaza_notifications`：`user_id/kind/title/body/submission_id/public_id/link/payload_json/read_at/created_at`，
    未读索引 `(user_id, read_at)`；
  - `plaza_favorites`：`UNIQUE(user_id, submission_id)`，记录收藏时题号；
  - `plaza_quality_checks`：`submission_id/version/release_id/public_id/checker_id/decision/severity/findings_json/
    note/auto_withdrawn/created_at`；
  - `plaza_issues` / `plaza_reports` / `plaza_appeals`：`status ∈ pending/resolved/rejected`、
    `resolution/handled_by/created_at/updated_at/resolved_at`，各自按投稿/状态/用户建索引。
- 新增常量（`db`）：`QUALITY_DECISIONS`、`QUALITY_SEVERITIES`、`QUALITY_AUTO_WITHDRAW_SEVERITIES=('high',)`、
  `QUALITY_SAMPLING_MODE='initial_100'`、`QUALITY_SAMPLING_REQUIRED=True`、`QUALITY_QUEUE_STATUSES`、
  `FEEDBACK_STATUSES/ACTIONS/LABELS`、`ISSUE_FIELDS`、`REPORT_REASONS`、`APPEALABLE_STATUSES`、
  `NOTIFICATION_KINDS`（20 类）；运营队列脱敏 `db.masked_display()`（`前缀·sha256 前 6 位`，不可反推）。
- 既有 8 张广场表未改列结构：回滚复用 `plaza_releases.status/active_public_id/withdraw_mode/reason/withdrawn_at`。

### 3.3 抽检与 `high` 自动撤回（`app/plaza/quality.py`）

- 抽检队列 `GET /api/plaza/admin/quality/queue`：按最新一次抽检结论给出 `pending/checked/passed/issues` 过滤与
  `counts`；`sampling` 返回 `mode/required/label/published_total/checked_total/pending_total/coverage_rate`
  （试点首批 100% 抽检的覆盖率提示）；只列已发布题或已有抽检记录的题，抽检员身份脱敏。
- 记录结论 `POST /api/plaza/admin/quality/checks`：只对「已发布 + 活跃发布指针」的题（否则 409）；
  抽检员回避本人投稿（403）；`issue` 需给出严重度（缺省 `medium`）与 `findings`（缺失 422）；`pass` 清空严重度。
- **`high` 自动撤回**：同一事务调用 `release.withdraw_active_release(mode='emergency',
  event_action='quality_withdrawn')`——发布指针与投稿状态置 `withdrawn`、写事件、通知作者与收藏者；
  抽检行 `auto_withdrawn=1`；响应 `auto_withdrawn:true` + `withdraw` 摘要 + `notified{author,favoriters}`。
  撤回即时影响广场公开读与 official 精选检索/详情/作答；历史作答保留。
- 非 `high` 的 `issue` 只记录并通知作者修订（`quality_issue`）；抽检记录只增不删（同一版本可多次抽检）。

### 3.4 通知中心（`app/plaza/notify.py`）

- 只发给相关用户（作者/收藏者/评审员本人/反馈人），`notify_many` 按 `user_id` 去重并支持 `exclude`（如排除作者）；
  正文只写事件与处理结论，不含他人身份与评审原文；通知与状态更新同事务。
- 20 类通知集中登记（`db.NOTIFICATION_KINDS`，只追加）：送审/改版/初审通过/初审退回/核验通过/争议/发布/
  撤回/回滚/作者撤回/收藏撤回/收藏恢复/抽检问题/抽检撤回/纠错处理/纠错驳回/举报处理/举报驳回/申诉受理/申诉驳回。
- 钩子接入既有链路：`submissions.py`（送审、改版、作者撤回并通知收藏者）、`review.py`（初审、核验阈值、
  争议，含对参与评审员的结论通知但不泄露身份）、`release.py`（签发、撤回、回滚）、`quality.py`、`feedback.py`。
- 接口：`GET /notifications`（只本人，`unread_only/kind/page/page_size≤100`，返回 `unread_count`）、
  `POST /notifications/read`（`{ids≤200}` 或 `{all:true}`，至少一项否则 422；他人通知忽略不报错）。

### 3.5 收藏（`app/plaza/favorites.py`）

- 只有当前公开可见题可收藏（`PUBLIC_STATUSES` + `figures.submission_publicly_visible`，`published` 还需活跃发布）；
  不可收藏 **409**（带状态），未知题号 **404**；`UNIQUE(user_id,submission_id)` 保证幂等。
- 我的收藏按当前投稿状态实时投影：撤回后保留记录、`available:false`、`notice` 提示；不删除用户收藏。
- 公开详情 `GET /api/plaza/questions/{public_id}` 增加 `favorited`（匿名 false）/`favorite_count`；
  撤回/争议状态页同样返回（便于前端显示收藏状态）。

### 3.6 纠错 / 举报 / 申诉（`app/plaza/feedback.py`）

- 纠错 `POST /questions/{public_id}/issues`：字段白名单 `stem/options/answer/explanation/figure/source/other`，
  描述 2–4000 字；举报 `POST /questions/{public_id}/reports`：原因白名单 `copyright/privacy/answer_error/
  content_quality/spam/other`；两者都要求题目当前公开可见（未知 404、不可反馈 409），写入事件并返回脱敏条目。
- 作者申诉 `POST /submissions/{id}/appeals`：仅作者本人（他人 404）、仅 `rejected/withdrawn/disputed`（否则 409），
  同投稿待处理申诉幂等返回（HTTP 200）；`GET /submissions/{id}/appeals` 作者看本人、编辑/管理员看全部。
- 编辑端 `GET /admin/issues|reports|appeals`（状态 `pending/resolved/rejected/all`，未知 422 对象）+ `counts`；
  处理 `PATCH /admin/{kind}/{id}`：`resolve`/`reject` + 可选说明，驳回必须给原因（<2 字 422），
  重复处理 409；同事务写事件并通知提交人；反馈人脱敏展示。
- `service.submission_detail` 为作者/编辑补充 `appeals`/`my_appeal` 与 `can.appeal`；前端投稿台据此显示申诉入口。

### 3.7 质量指标（`app/plaza/metrics.py`）

- `GET /api/plaza/admin/metrics` 由后端集中计算（编辑台只展示、不重算）：
  题量/状态/学科/题型分布；公开可见题**可判分率**（快照含参考答案）；**图可用率**（当前版本公开衍生图覆盖）；
  **评审时长**（`initial_review_accepted→threshold_met` 与 `submitted→published` 中位小时数）；
  **抽检问题率**（issue/high 占比、待抽检数、100% 抽样覆盖率，抽检后被撤回的题仍计入发布基数）；
  **反馈积压**（纠错/举报/申诉 total 与 pending）；**撤回/回滚数**（发布撤回、投稿撤回、`release_rolled_back` 事件）。
- 返回 `caliber` 中文口径说明，运营口径不做个性化；指标接口仅编辑/管理员。

### 3.8 回滚与撤回传播（`app/plaza/release.py`）

- `POST /api/plaza/submissions/{id}/rollback {reason(2–2000)}`：仅编辑/管理员（作者回避 403）；要求
  「当前有活跃发布 + 存在更早的已撤回历史发布 + 该版本快照仍在」，否则 409（带 JSON 详情）。
- 同一事务：当前发布 → `withdrawn`（`withdraw_mode='rollback'`、原因）；上一发布 → `active`
  （恢复 `active_public_id`）；投稿主表恢复该历史版本快照/来源/指纹/授权并 `status='published'`；
  重新登记公开图；写 `release_rolled_back` 事件（含 from/to version、figures 摘要）；通知作者（`release_rolled_back`）
  与收藏者（`favorite_restored`）。条件 UPDATE 保证并发下只成功一次，`active_public_id` 唯一索引保证单一活跃发布。
- 撤回（normal/emergency）与回滚都只改「发布指针 + 投稿状态/版本」；公开读与 official 精选读取均在查询时判定，
  因而即时生效；历史作答/成绩/收藏记录保留。

### 4.1 用量账本与生命周期入账（`app/ai/usage.py` + `app/ai/jobs.py`）

- 新增 [`app/ai/usage.py`](../app/ai/usage.py)：`ai_job_usage`（**每任务终态一行**，`job_id` 唯一幂等）记录

  可追踪账本；两表以 `job_id` 关联，互不覆盖。

### 4.2 配额与全站并发（`check_new_job` / `current_concurrency`）

- 优先级：管理员 `ai_quotas` 覆盖（db）→ 环境变量 `STUDY_AI_QUOTA_<KIND>` / `STUDY_AI_CONCURRENCY_<KIND>` →
  内置默认（17 个任务类型）→ 未配置（不阻断，仅日志警告）；`0` 表示不限制。
- 每人每日配额按 **UTC 自然日**统计 `ai_jobs` 中 `status NOT IN ('failed','cancelled','interrupted')` 的任务数：
  **失败/取消/中断不消耗配额**；全站并发按 `kind` 统计 `queued/running/cancel_requested/awaiting_outline`
  （数据库为跨进程权威来源，异常时退化为进程内注册表）。
- 超限在**写库前**抛 **429** `{code:'ai_quota_exceeded', kind, message}`：请求不落库、不消耗配额，
  提示为中文且带任务名与限额；管理接口调整配额后立即生效。

2. **撤回后的历史可读范围**：题目撤回后，`official:` 详情/`/api/reveal` 均 404，历史作答只能看到结果与
   错题/复习占位卡（题面与答案不可再展开）；若运营需要「历史成绩可回看题面」，需要在撤回前保留合法快照或提供
   受限历史视图（方案 §5 允许在授权范围内保留必要记录）。
3. **抽检 100% 与自动撤回是产品默认值**：`QUALITY_SAMPLING_MODE`/`QUALITY_AUTO_WITHDRAW_SEVERITIES` 集中常量，
   调整只改常量；`high` 自动撤回影响面大，需运营明确严重度口径与复核责任。
4. **通知/事件表只增**：`plaza_notifications`/`plaza_events` 只追加，长期需归档/保留策略；通知按相关用户写入，
   避免把评审意见原文扩散。
5. **回滚依赖历史发布行**：同一投稿多次发布/回滚/改版需保证历史 release 完整；`db.next_version()` 会跳过已留档
   版本号，避免 `UNIQUE(submission_id,version)` 冲突；回滚恢复旧 `public_id` 后，旧链接重新可用（历史链接会指向
   恢复版本，需运营知悉）。
6. **配额默认值**：17 类任务的每日/并发默认值为保守起步，可能过紧（误伤正常使用）或过松（无法防滥用）；
   管理员/环境变量可覆盖，调整需结合真实流量。
7. **前端能力探测依赖 422 语义**：来源筛选/精选计数/通知等用「非法请求得到参数校验错误」判断后端是否就绪；
   若后端未来改变错误码/文案，探测正则（`sourceParamSupported` 等）需同步，否则会误判为未就绪或误显示。
8. **AI 费用口径**：`cost_micro` 仅按模型设置单价估算，不代表真实账单；未配置单价时为 `null`（前端显示未知），
   不得把它当作真实费用对账依据。
9. **轮次编号口径**：仓库既有第一份记录标题为「第二轮」、第二份文件为「第二轮」，本文件为「第三轮」；
   三者是先后承接关系，对外引用建议用日期 + 范围区分，避免仅凭「第 N 轮」误解轮次。
