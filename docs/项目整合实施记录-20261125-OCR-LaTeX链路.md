# OCR→LaTeX 链路打通实施记录（2026-11-25）

对应《项目现状审查与功能联合整合赋能方案》拍题入库主线的补全：让「识别 → 校对 → 保存 →
展示」全链路的公式都以 LaTeX 为载体，最终给用户展示标准排版（KaTeX）而不是字面代码。
本轮同时把此前审查发现的选项拆分正则收紧（`[A-La-l]` → `A-D`）。

## 1. 问题（审查结论）

识别层（RapidLaTeXOCR，可选）与校对层（formulaInput 实时预览）早已就位，但断在两处：

- **保存层**：`_parse_question_text` 只用纯文本行拼题干；公式块 `latex` 只在草稿
  `blocks` 里，用户要逐块手动「插入公式」，没有一键按阅读顺序合并；
- **渲染层**：`questionText()`（题干/选项的兜底渲染）对 `$..$` 生成纯文本节点；个人题
  在练习页的题干又总是走 `stem_blocks` → `textBlockNode`（只处理 `_{}/^{}` 下上标），
  两处都不渲染 LaTeX——而整卷 `paperDocument.js` 对个人题走 `markdown(stem)` 能渲染，
  同一道题两处显示不一致。

## 2. 修改

### 渲染层（`web/js/core/dom.js`）

- 新增 `STEM_MATH_SPLIT_RE` / `mathSnippetOf` / `appendMathSnippet` /
  `appendMathAwareText`：与 `core/markdown.js` 的 `preprocessMath` 同一口径——
  `$$..$$` 与 `\[…\]` 独立公式、`$..$`（禁换行、首尾不留空白）与 `\(…\)` 行内公式；
  纯数字（价格）不当作公式；
- 渲染走 `renderMath(throwOnError:true)` + 输出检查（`katex-error/math-fallback` 视为
  失败）+ `sanitizeMath` 白名单净化，任一步失败回退纯文本节点，不写未净化 HTML
  （与 `mathBlockNode` 同一 fail-closed 策略）；
- `questionText()`：占位符（`[图N]/[公式N]`）逻辑不变，其余文本段数学感知；
- `textBlockNode()`：含数学定界符的文本块走同一套渲染（个人题题干的主路径），
  不含定界符的老题保持原有 `markedText` 下标/上标逻辑，零回归。

### 保存层（`web/js/pages/upload.js` + `web/js/components/formulaInput.js`）

- 识别块校对区新增「按识别顺序合并到题干」按钮：以公式输入组件的**实时值**为准
  （与 `currentBlocksPayload` 同口径），text 块取原文、math 块取 `$latex$`（无 LaTeX
  回退原文）、image 块跳过，按行拼接替换题干草稿（20000 字上限与后端一致）；
- 语言包新增 `study.formula.review.mergeAll / mergeDone / mergeEmpty`（zh/en 各 3 键），
  `formulaInput.js` 内置中文兜底文案同步。

### 识别层（`app/ai/upload_pipeline.py`）

- 选项拆分正则 `_OPTION_LINE_RE` 由 `[A-La-l]` 收紧为 `[A-Da-d]`：小写 a–l 开头的
  题干列表行（如 `l. 1600 年…`）不再被误吞为选项（选项极少超过 D，误拆反而吞题干）。

## 4. 边界与后续

- `$..$` 识别与 markdown.js 同口径：价格（`$5`/`$3.50`）按原文显示；未配对的 `$`
  保持字面；非法 LaTeX 回退原文，不阻塞阅读；
- 官方题库题仍以 `[公式N]` 占位 + 原卷公式图为主，`stem_plain` 路径不经本轮改动；
- 公式自动识别仍需 `STUDY_FORMULA_OCR=on` + 安装 rapid-latex-ocr（设置页引擎总览
  如实显示状态）；未启用时用户可手动粘贴 LaTeX 或用 MathLive 编辑器插入，保存后
  同样得到标准排版。
