## 2. 设计：一个到期值，两条兼容路径

```
四档评分 ─┐
          ├─→ review_cards.due_at（权威，算法/版本落库）
普通判分 ─┘        │ 同一事务镜像（_mirror_due_to_wrong）
                   ▼
        wrong_questions.next_review_at（只读兼容字段）
                   │
      ┌────────────┼──────────────┬───────────────┐
   首页/学情    错题本/复习队列   /api/reviews    /api/stats、Anki 导出
```

- **权威方向**：卡有真实评分（`reps>0`）→ 卡赢，旧表跟随卡；卡未评分 → 旧表（普通判分/迁移）赢，卡跟随旧表。
  归档标记始终从旧表同步到卡，归档卡不参与到期对齐。
- **镜像时机**：`rate_card` 更新卡后、`sync_wrong_question`（作答/重判后同事务调用）同步时、
  惰性迁移补卡后（自愈漂移）。镜像同时更新 `interval_days`（按到期与当前时钟的天数差，至少 1 天）。
- **惰性迁移**：`ensure_user_cards(user_id)` 对比「错题 qid 集合」与「卡面键集合」，缺卡才调用
  `sync_user_cards`；已有卡时只做两次小查询、不写库。由 `due_cards/stats/compare_due/due_map` 统一触发，
  因此首页/错题/复习/统计任一首次读取都会完成迁移。
- **时钟**：`practice._review_clock_iso()` 统一到期比较时钟（默认 `db.utcnow()`；`STUDY_REVIEW_CLOCK`
  固定时与复习模块一致）。真实生产两者都是服务端 UTC，不影响旧口径。
