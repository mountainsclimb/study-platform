## 2. 精选接入收尾（助手 / 课堂 / 学情口径 / 学段筛选）

### 2.1 读取层补齐（`app/official.py`）

- 新增 [`official_caliber(user_id=None)`](../app/official.py)：平台精选统计口径，返回
  `available/total_questions/practice_pool/auto_gradable/attempts/practiced/wrong_count/due_reviews/caliber/note`。
  只统计**当前公开可见**精选题（`community_review`/`verified`/`published` + `public_id` 非空；`published` 还需活跃发布指针），
  撤回/争议在查询时剔除且不做进程内缓存；本人已练/错题/到期复习按题目当前可见性过滤（撤回题历史保留但不计入）。
  广场表不可读时降级为 `available:false` + 中文 `note`，不阻断首页/统计。
- 新增学段筛选工具：`GRADE_STAGES=("小学","初中","高中")`、`STANDARD_GRADES`（12 个标准年级）、
  `GRADE_FILTER_MAX_CHARS=40`；`normalize_grade_filter(value)` 返回
  `{requested,values,stages,valid,degraded,reason}`（逗号分隔多值、标准年级精确匹配、学段前缀匹配；
  未知值/过长**安全降级不 422**），`matches_grade(grade_value, normalized)` 按**快照 grade** 匹配。
- `search_official()` 增加 `grade` 参数（可传原始字符串或规范化结构）：官方侧按快照 grade 过滤；
  `type` 仍同时接受工坊题型与练习题型（未知 **422**）；排序仍为「精选 > 核验通过 > 待核验，再按更新时间」。
- 投影（`_project`）补 `grade`（快照年级）并保持既有 `public_id/official_status/review_status/published_version/
  figure_notice/source_declaration` 等字段不变；读取/可见性语义与第三轮一致（不可见统一 404，不回显受限正文）。

### 2.2 AI 助手接入 official（`app/assistant.py`）

- 工具白名单新增只读工具 [`search_official`](../app/assistant.py)（`keyword?/subject?/grade?/qtype?/limit 1-10`）：
  至少给一个检索条件（否则 `ToolError` 中文提示）；返回条目含
  `qid/source/source_label/public_id/review_status(_label)/status_label/published_version/featured/community_pending/
  subject/grade/type/stem(≤160)/has_answer/knowledge_tags(≤5)`，`refs` 带 `qid/source/public_id/review_status`；
  检索总数与精选命中数写入 summary；**不输出内部 ID/投稿人/审核员**。
- `read_question` 扩展接受 `official:<公开编号>`：先按统一引用解析（格式不正确 → 中文错误而不是 500），
  读取走 `practice.load_question`/`official.load_official_question`；撤回/争议/不可见时通过
  `inspect_official` 生成明确中文提示（“已撤回/有争议/当前不可见…历史作答、错题与成绩记录保留”，
  **绝不回显题面/选项/答案**）；作答门控沿用「本人已作答才返回答案与解析」，并在工具结果中给出
  `source=official`/`public_id`/`official_status`/`review_status(_label)`/`published_version`/`source_declaration`
  与「回答中引用时写「平台精选 <公开编号>」，不要提任何内部 ID、投稿人或审核员信息」的下一步提示。
- 系统提示新增第 5 条安全规则：平台精选题只引用工具返回的公开信息，引用时必须写「平台精选 · 公开编号 plz-...」
  并说明审核状态，绝不透露/猜测内部 ID、投稿人、审核员与后台字段；已撤回/有争议的题目不得复述题面、答案或解析。
- `get_stats` 工具结果新增 `official`（与 `/api/stats` 同源）；`available` 时 summary 追加
  「平台精选已练 X 道（可练 Y 道）、精选错题 Z 道」。
- 工具能力边界 `/tools` 的 `scope_note` 明确「只读高考题库 + 当前公开可见的平台精选」；
  本轮工具数 12 → **13**（新增 `search_official`），写操作工具集合不变。

### 2.3 课堂以精选题为素材（`app/classroom/{api,generate,prompts}.py`）

- 建课生成参数 [`GenerateInput.source_ref`](../app/classroom/api.py)（`max_length=160`）：
  目前**只开放平台精选**（`SEED_QUESTION_SOURCES=("official",)`）。
  `generate.normalize_seed_source_ref()`：来源不支持/格式非法 **422**（中文说明格式 `official:<公开编号>`）；
  未发布/撤回/争议在 `resolve_seed_question()` 中按查询时可见性 **404**（撤回题提示「不能再作为新课程素材；
  历史课程保留当时的来源标记」）。
- 大纲 prompt 注入：`generate.format_seed_question_material()` 生成「公开编号/审核状态/学科/学段/知识点/题面/
  选项/参考答案（仅供备课设计）/解析要点/来源声明/公开提示」，`prompts._official_seed_block()` 限定
  `OFFICIAL_SEED_PROMPT_MAX_CHARS=4000` 并规定：场景引用必须写「平台精选 · 公开编号 plz-...」并保留审核状态、
  **不得编造公开编号/来源声明/题目没有的数据**、答案要点只用于备课（学生题面保持先作答再揭晓）、
  不输出内部 ID/投稿人/审核员。
- 来源与版本留痕：`generate.official_source_entry()` 生成 `outline.sources` 条目
  `{index,kind:'official',title,url:'',site:'平台精选',date:'',summary,question_ref,public_id,
  published_version,review_status(_label),subject,grade,source_declaration}`；课程 `config.seed_source` 记录
  `source_ref/public_id/published_version/review_status(_label)/title`，`outline_sources()` 同时清洗 web/official
  两类来源（损坏缺失安全返回空列表）。任务结果追加
  `official_source_count/official_sources[]`（公开编号/版本/审核状态/来源声明），summary 追加
  「课程素材来源：平台精选 plz-xxx（vN）」。
- 校验时机：`validate_course_job()` 只在 `stage ∈ (outline, all)` 且**还没有大纲**时校验素材可见性——
  已有大纲的续跑/单场景重生成不重新引用素材，因此题目后续撤回不影响既有课程与导出；`run_course_job()`
  生成大纲时再按当前可见性读取一次（撤回 → 任务失败原因可读，不落 500）。
- 导出/回看：既有 `outline.sources` 导出链路（PPTX 末页 / 离线 HTML / ZIP `sources.json` / 资源包 README /
  讲义打印）直接保留 official 来源条目；`exports._course_sources()` 统一走 `outline_sources()` 清洗。

### 2.4 学情 / 首页 / 统计的 official 口径

- [`app/practice.py::stats`](../app/practice.py)（`GET /api/stats`）新增嵌套 `official` 块（同一 `official_caliber`）；

### 2.5 学段筛选（`GET /api/questions?grade=` 与 catalog 元数据）

- [`app/practice.py`](../app/practice.py) `list_questions()` 新增 `grade: str | None`：
  - official 侧用**快照 grade**（标准年级精确匹配 / 学段前缀匹配）；题库侧仅当题库存在 `grade` 列时生效
    （`grade_values`/`grade_stages` 生成 WHERE；SQL 为 `q.grade IN (...) OR q.grade LIKE '学段%'`）；
  - 非法/未知值**不 422**：响应追加 `grade_filter:{requested,applied,bank_applied,official_applied,values,stages,reason}`；
    题库无年级列时 `applied:false` + 中文 reason「当前只读题库没有年级字段，学段筛选在题库侧暂不生效
    （平台精选按快照年级过滤）」；
  - `source=bank|official|all` 的合并分页语义不变：`all` 仍按「题库在前、精选在后」的合并偏移严格分页，
    学段筛选对两侧分别生效并在 `grade_filter` 中分别标记。
- [`GET /api/catalog`](../app/practice.py) 新增 `grades`（优先 `paperlab.db.GRADES`，否则内置 12 个标准年级）、
  `grade_stages`（小学/初中/高中）、`grade_note`（口径说明）；既有学科/题型/省份/年份/难度元数据不变。
- 边界：`r5` 只读题库没有 grade 列，因此当前 `source=bank` 的 `grade` 筛选是**安全降级不生效**（不是 422 也不是 500），
  平台精选与未来带 grade 列的题库按同一参数生效；前端据此显示「仅平台精选生效」说明而非假筛选。

## 3. 运维监控（方案 §7「分发与运维」）

### 3.1 接口与访问（`app/monitor.py` + `app/main.py`）

- 新增 [`app/monitor.py`](../app/monitor.py)（只读聚合，router prefix `/api`）与
  [`GET /api/admin/monitor`](../app/monitor.py)：
  - 访问 `monitor_access()`：管理员会话（`role='admin'`）**或** 部署探针口令
    （`STUDY_HEALTH_TOKEN` + `X-Health-Token`，复用 `app.main._health_token_ok` 常量时间比较，只读）；
    否则未登录 **401**「请先登录」、非管理员 **403**「需要管理员权限」；请求 `via` 字段区分 `session`/`health_token`。
  - 查询参数 `refresh: bool`（`refresh=1` 绕过进程内短缓存重新采集）。
  - `app/main.py` 只做最小接线：`app.include_router(monitor.router)`（无新任务类型、无启动初始化副作用）。
- 响应结构：`{ok, status, generated_at, duration_ms, build:{build_id,version,bank_version}, window_days,
  thresholds{...}, degraded[], checks:{tasks,ai,media,data,plaza}, cache:{ttl_seconds,cached,age_seconds}}`；
  `ok = (整体 status != 'error')`，`status` 取五组中最严重的 `ok<warn<error`。

### 3.2 五组检查项（字段以 `_result(...)` 返回为准）

| 分组 | 关键字段 | 告警口径（阈值为集中常量/环境变量） |
|---|---|---|
| `tasks` | 按 kind 的 `queued/running/cancel_requested/awaiting_outline/completed/failed/interrupted/cancelled`、`failure_rate`、`oldest_queued_seconds`、`timed_out`、`stale_running`、`reclaimed`（中断回收）、`success_rate`、`totals`、`by_kind[≤20]` | 近 `window_days` 天终态 ≥4 且失败率 ≥25% → warn；最老排队 ≥120s → warn / ≥900s → error；执行超时或心跳超期（租约）→ warn |
| `ai` | `source`（`ai_job_usage` 优先，账本不可读退回 `ai_jobs` 粗算并告警）、`totals{jobs,failed,cancelled,failure_rate,duration_p50/p95/avg_ms,tokens_in/out/total,retries,cost_micro,cost_covered_jobs,cost_unpriced_jobs}`、`by_kind[≤20]`、`ocr`（`kind ∈ ocr/recognize` 的同口径聚合 + `kinds`）、`model_calls`（`ai_usage` 逐次调用数，仅增强信息） | 账本缺失/不可读 → warn；失败率 ≥25%（≥4 任务）→ warn；OCR P95 ≥120s 或 OCR 失败率 ≥30%（≥3 任务）→ warn |

### 3.3 只读、降级与缓存语义

- **只读**：只执行 `SELECT`/只读探测（题库以 `mode=ro` 打开；备份只读 ZIP 内 `manifest.json`，>2MB 不读），
  不写任何业务表、不触发广场/AI 业务函数；不输出密钥、绝对宿主路径或用户内容。
- **单检查失败不 500**：`_run_check()` 每个检查独立数据库连接 + 独立异常边界（PG 事务 aborted 不外溢），
  抛错只把该组标 `status=error` 并给出中文 `detail`/`alerts`，其余组照常返回；整体 `ok=false`。
- **短缓存**：`collect_monitor()` 进程内缓存，`STUDY_MONITOR_CACHE_SECONDS`（默认 15s，0 关闭，最大 300s）；
  缓存键 `(db.DATA_DIR, postgres_enabled(), ai_window_days())`，数据目录/引擎/统计窗口变化自动失效；
  命中时响应 `cache.cached=true` + `age_seconds`；`refresh=1` 或 `reset_cache()` 绕过。
- 统计窗口：`STUDY_MONITOR_AI_WINDOW_DAYS`（默认 7，1–365）；超时阈值
  `STUDY_MONITOR_JOB_TIMEOUT_SECONDS`（回退 `STUDY_WORKER_JOB_TIMEOUT`，默认 1800）、租约
  `STUDY_MONITOR_LEASE_SECONDS`（回退 `AI_JOB_LEASE_SECONDS`，默认 90）；WAL/备份/反馈阈值分别由
  `STUDY_MONITOR_WAL_WARN_MB`（64）、`STUDY_MONITOR_BACKUP_WARN_HOURS`（48）、
  `STUDY_MONITOR_FEEDBACK_WARN_PENDING`（20）覆盖；单次查询行上限 `QUERY_ROW_LIMIT=5000`、撤回抽样 `SAMPLE_LIMIT=200`。
- 广场模块不可用时用本地兜底常量 `_FALLBACK_PUBLIC_STATUSES`/`_FALLBACK_KIND_LABELS`，监控不反向依赖广场业务代码。

## 4. 质量运营闭环（门禁 / 恢复 / 批量 / 通知增强 / 指标）

### 4.1 抽检门禁（`app/plaza/gate.py` + `plaza_quality_gate_log`）

- 模式 `GATE_MODES=('off','initial_100','always')`，默认 `initial_100`；标签与 409 guidance 集中为中文常量；
  解析优先级：**管理员运行期设置**（`app_settings.plaza_quality_gate`，经管理接口修改立即生效）→ **环境变量**
  `STUDY_PLAZA_QUALITY_GATE` → 内置默认；未知模式回退默认并在 `mode_source` 标注 `:invalid`。
- `armed`（试点激活）：显式配置了模式（管理设置或环境变量且非 off）或库中已有任意抽检记录时视为已激活；
  也可用 `plaza_quality_gate_armed`/`STUDY_PLAZA_QUALITY_GATE_ARMED` 显式 true/false
  （`armed_source=setting|env|auto`）。试点窗口按「成功签发数」（`plaza_releases` 行数）计数，
  `pilot_limit` 默认 100（`0` 不设上限，`pilot_remaining` 给出剩余），窗口结束后 `initial_100` 不再阻断（稳定期改常规抽检）。
- 判定 `evaluate(con, submission, version)`：`off` → 不阻断；未激活 → 不阻断（提示）；窗口结束 → 不阻断（提示）；
  否则要求该版本**最新一条独立抽检记录**为 `pass` 且抽检员 ≠ 作者（`_independent_pass`）；未满足 → `blocking=true` +
  `OVERRIDE_GUIDANCE`（先抽检再签发；紧急情况编辑显式 override，写审计与指标）。
- 签发接线 [`release.publish_submission`](../app/plaza/release.py)：在既有「状态/授权/阈值」校验之后、写发布指针之前评估门禁；
  阻断时抛 `QualityGateBlocked` → 事务回滚 → 独立事务 `record_blocked` 写审计 → **409**
  `{code:'quality_gate_blocked', message, submission_id, version, mode, mode_label, guidance, override_allowed:true,
  latest_check, gate:{mode,armed,enforced,required,window_open,pilot_limit,published_total}}`（不泄露抽检员身份）。
- override：请求体 `PublishInput.quality_gate_override=true` + `override_reason`（≥2 字，否则 **422** 对象带 guidance）；
  同事务写 `quality_gate_override` 事件（mode/version/latest_check/guidance）与门禁审计行 `outcome='override'`；
  正常通过写 `outcome='passed'`；签发事件 payload 追加 `quality_gate{mode,armed,required,override,override_reason,pass_check_id}`；
  响应 `quality_gate{...}` 完整回显模式/激活/窗口/是否 override。
- 审计表 `plaza_quality_gate_log(id, submission_id, version, mode, outcome, actor_id, reason, created_at)`，
  `GATE_OUTCOMES=('blocked','override','passed')`；状态接口 `GET /api/plaza/admin/quality/gate`（编辑/管理员）返回
  配置 + `counts{blocked,override,passed}` + `override_total/blocked_total/passed_total/evaluated_total/by_mode/recent[≤10]/notice`；
  `PUT /api/plaza/admin/quality/gate`（**仅管理员**）`{mode?,armed?,pilot_limit?,reset?}`，非法模式/负窗口 **422**，`reset` 删除设置恢复默认。

### 4.2 签发前抽检（`app/plaza/quality.py`）

- 原抽检接口 `POST /api/plaza/admin/quality/checks` 扩展为两阶段（`db.QUALITY_CHECK_PHASES=('post_publish','pre_publish')`）：
  - `post_publish`：`status='published'` 且有活跃发布（既有口径）；
  - `pre_publish`：`status ∈ QUALITY_PRE_PUBLISH_STATUSES=('verified','pending_release')` 且无活跃发布
    （社区核验通过、待平台签发）——通过后编辑即可签发；`community_review` 仍 **409**（保持既有语义）；
  - 其它状态 **409** 对象（含 `status/status_label`）；`pass` 清空 severity/findings，`issue` 缺 findings **422**。
- 发布后抽检 `high` 自动撤回逻辑不变（同一事务 `withdraw_active_release(mode='emergency',
  event_action='quality_withdrawn')`）；签发前抽检的 `high` **不会撤回**（尚无发布），只记录问题并通知作者修订。
- 响应追加 `phase`、`gate{mode,mode_label,mode_source,armed,enforced,required,blocking,publish_ready,guidance,
  override_guidance}` 与 `notified{author,favoriters}`；`publish_ready` 仅在签发前抽检 `pass` 且未阻断时为 true。

### 4.3 一键恢复（`POST /api/plaza/releases/{public_id}/restore`）

- 仅编辑/管理员（作者回避 **403**）；记录不存在 **404**；已是活跃发布 → **200** 幂等
  `{idempotent:true, message:'该发布已处于活跃状态，无需重复恢复'}`。
- 只能恢复**该公开题最近一次被撤回的发布**，且撤回来源必须是「抽检 high 自动撤回」或「编辑撤回」；
  `withdraw_mode='rollback'` 的回滚撤回 **409**（提示重新送审签发）；其它来源 **409**。
- 硬性条件（均 **409**，带 JSON 详情）：该投稿已有更新版本的活跃发布（`active_public_id/active_version`）、
  投稿 `current_version` 与要恢复版本不一致（`current_version/restore_version`）、投稿当前状态不是 `withdrawn`、
  历史版本快照 `plaza_submission_versions` 缺失；未确认问题已处理 **422**（`field:'confirm_resolved'` + guidance）；
  理由 <2 字 **422**。
- 同事务完成：发布记录 `status='active'`（清空 `withdrawn_at/withdraw_mode/reason`，CAS 条件 UPDATE 防并发）→
  投稿主表恢复该版本快照/来源/指纹/授权并 `status='published'`（CAS `WHERE status='withdrawn' AND version=?`）→
  重新登记公开衍生图 → 写 `release_restored` 事件（release_id/public_id/version、`source=quality_auto_withdraw|
  editor_withdraw`、`quality_check_id`、`previous_withdraw{mode,reason,withdrawn_at}`、`confirm_resolved:true`、figures 摘要）→
  通知作者（`release_restored`）与收藏者（`favorite_restored`）。
- 响应 `{submission{status:'published',version,current_version,public_id,public_visible:true}, release,
  restored_release, restored_version, restore_source, previous_withdraw, quality_check, notified{author,favoriters},
  figures, public_url, idempotent:false, message}`。恢复后公开读（列表/详情/公开图/official 检索）即时可见，
  历史作答/成绩/收藏记录保留。

### 4.4 批量处理（`POST /api/plaza/admin/{issues|reports|appeals}/batch`）

- 请求 `{ids:[1-50], action:'resolve'|'reject', reason?}`：ids 去重、非正数忽略；空 ids **422**；
  超过 `MAX_BATCH_ITEMS=50` **422**（带 `max_items`）；批量驳回必须给原因（<2 字 **422**）。
- **部分成功语义**：同一事务内逐条处理，不存在 → `skipped[{id,reason:'not_found',message}]`；
  已处理/非 pending → `skipped[{id,reason:'already_handled',status,status_label,message}]`；
  单条冲突（HTTPException）→ `skipped[{id,reason:'conflict',message}]`；成功条目走 `_apply_feedback`
  （状态 + 事件 + 通知提交人）。成功条目不因其它条目失败而回滚整批。
- 响应 `{kind,kind_label,action,target_status,requested,updated[≤50],updated_ids,updated_count,skipped,skipped_count,
  batch_id,max_items,message}`；每次批量动作在 `plaza_ops_batches` 写一行审计
  （`kind/action/requested/updated/skipped/actor_id/reason/created_at`），供指标聚合。
- 权限：`service.require_plaza_role("editor")`（管理员直通）；写锁 `plaza-write`。

## 9. 风险与注意事项

1. **门禁 `armed` 自动激活**：未显式配置模式时，只要库中已有任意抽检记录即视为试点已激活（避免生产试点显式配置后
   不生效）；在已有抽检历史的环境升级后，新的签发会立即受门禁约束——上线前需确认运营已准备好「先抽检再签发」流程，
   否则会遇到 409 + override 路径。
2. **试点窗口按成功签发数计**：`pilot_limit=100` 统计的是 `plaza_releases` 行数（含历史行），已有大量发布的环境
   窗口可能直接关闭；需要时用 `PUT /admin/quality/gate` 的 `pilot_limit`/`mode` 显式调整，调整会写设置并立即生效。
3. **override 可绕过门禁**：属于试点期紧急通道，只能靠审计（`plaza_quality_gate_log` + 事件 + 指标）事后追责；
   建议运营定期核对 `override_total` 与理由。
4. **一键恢复可能把旧版本内容重新公开**：restore 恢复的是「被撤回版本」的快照，因此 409 防护集中在「同投稿已有更新
   版本活跃/current_version 不一致」；若运营在撤回后又编辑过投稿但未改版本号，恢复前应人工核对内容。
5. **监控缓存 15 秒**：`GET /api/admin/monitor` 命中缓存时数据最多滞后 `STUDY_MONITOR_CACHE_SECONDS`；排障时用
   `refresh=1` 强制刷新；缓存按进程隔离（多 Worker 各自缓存）。
6. **通知去重窗口可能合并重复事件**：同「接收人+类型+投稿+版本」在窗口内只保留一条；对需要逐次留痕的事件
   （如连续多次抽检问题）应查看事件链 `plaza_events`，不能只看通知条数。
7. **构建指纹成本与边界**：启动时对源码/前端/editor vendor 计算 sha256（文件数较多时增加启动开销）；`STUDY_BUILD_ID`
   显式覆盖时不做内容校验（镜像由 CI 写入提交号）；`.dockerignore` 排除 `editor/dist/` 是有意为之（构建产物以
   `web/editor` 随包），如需镜像内重建编辑器的部署方式应调整该规则。
8. **official 口径查询成本**：`official_caliber()` 在首页/统计/助手 `get_stats` 调用时逐题统计可见集合与本人作答
   （分块 IN 查询），公开题量大时存在多次查询；检索仍为快照 JSON `LIKE`，后续可加发布状态物化视图/缓存
   （但需保证撤回即时性）。
9. **轮次编号口径**：仓库既有第一份记录标题为「第二轮」、第二份文件为「第二轮」、第三份为「第三轮」，本文件为
   「第四轮」；四者是先后承接关系，对外引用建议用日期 + 范围区分，避免仅凭「第 N 轮」误解轮次。
