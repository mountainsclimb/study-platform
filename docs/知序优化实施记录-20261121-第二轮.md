## 2. Phase 1 剩余

### 2.1 统一题目引用（`app/question_ref.py` + `app/practice.py` / `app/paperlab/practice.py`）

- 新增 [`app/question_ref.py`](../app/question_ref.py)：纯字符串工具（不导入数据库/HTTP），提供
  `parse/try_parse/build/normalize/split/storage_key/source_of/source_label/is_app/describe`、
  `submission_key/validate_submission_id/paper_item_key`。引用语法：`bank:<qid>`（裸 qid 按 bank，兼容旧客户端）、
  `app:<pl_questions.id>`（key 必须为正整数）、`official:<id>`（解析/规范化可用、读取层未开放 → 404
  「该来源题目暂未开放」）。上限：引用 ≤300 字符、`submission_id` ≤160 字符；非法引用统一 422，不 500。
- [`app/practice.py`](../app/practice.py) 接入点：`load_question_ref`（bank=只读题库、app=paperlab 归属校验、
  official=404）、`_assert_ref_owned`（写操作前 app 归属校验）、`_storage_qid`（写库键）、`_app_question_dict`
  （把 `pl_questions` 行投影成练习题目，`qid=app:<id>`、含 `app_content/app_type` 内部字段）。
  接受统一引用的接口：`GET /api/questions/{qid:path}`、`GET /api/reveal?qid=`、`GET /api/attempts/history?qid=`、
  `POST /api/attempts`、`POST /api/mastery`、`POST /api/wrongbook`、
  `GET /api/bank-image?qid=app:<id>`（个人题配图分支复用 `paperlab.assets.resolve_asset_for_read`，统一 404）。
- 投影兼容：`_public_question` 与个人题投影新增 `ref/source/source_label`，旧字段 `qid` 仍是写库键
  （题库裸 qid、个人题 `app:<id>`）；错题卡/复习队列/统计同步带来源字段。个人题删除后错题卡降级为
  `_missing_app_card`（历史成绩仍可读，不 500）。
- 工坊整卷侧：`app/paperlab/practice.py` 用 `question_ref.normalize` 归一化题项 `ref`，判分/错题联动按
  `ref.startswith("bank:") / "app:"` 分支；整卷逐题入账幂等键 `paper_item_key(attempt_id, item_position)`。

### 2.2 幂等入账与统一复习队列（`app/practice.py`）

- `submission_ledger`（`PRIMARY KEY(user_id, kind, ledger_key)`；`kind='attempt'` 单题、`kind='paper_item'`
  整卷逐题）在 `practice.init_practice()` 幂等建表。`POST /api/attempts` 新增可选 Form `submission_id`：
  校验（非空、≤160、`A-Za-z0-9._:+-`，非法 422）→ `submission_key = <写库题目键>|<submission_id>`；
  台账占用与 `attempts` 插入同一事务，唯一约束兜底并发；重复路径回放既有作答（`duplicate:true`），并发落败
  请求丢弃本次新存图片；不带 `submission_id` 保持旧的非幂等语义。整卷提交用 `_record_wrong(entry_key=...)`
  以 `paper:<attempt_id>:<item_position>` 幂等，`bank:`/`app:` 错题都写统一 `wrong_questions`，
  `app:` 题关联成功/未成功分别在 `app_wrong_added`/`app_bank_unlinked` 明示。
- 新增 `GET /api/review/queue`（`?subject&limit=1-200，默认 50`）：`items` 为已判分到期/历史错题
  （`graded:true`），`pending_items` 为最近一次作答仍 `pending` 的题（单列、不参与错题调度）；
  返回 `{items,pending_items,total,graded_count,pending_count,limit,message}`，条目含 `ref/source/source_label`。
- `GET /api/stats` 新增 `app_attempts/app_practiced/app_wrong_count`（个人题单独计数），
  既有 `total_questions/attempts/practiced/correct/accuracy/wrong_count/due_count/...` 不变。

### 2.3 个人收录版本与「有新版」（`app/paperlab/versions.py`）

- 数据层（[`app/paperlab/db.py`](../app/paperlab/db.py)）：新增 `pl_question_versions`（不可变版本历史，
  `UNIQUE(question_id,version)`、`origin ∈ create/edit/collect/source_update/snapshot`、`content_sha256`、
  `asset_refs_json`、`source_*`；无修改入口）与 `pl_questions` 来源列（`content_sha256`、`source_ref`、
  `source_kind`、`source_question_id`、`source_bank_version`、`source_content_revision`、
  `source_answer_revision`、`source_meta_json`、`collected_at`）；新库直接建列，老库 `ensure_column` 幂等补齐，
  来源列补完后建 `pl_questions(user_id, source_ref)` 索引，不重建表。
- 接口（`app/paperlab/bank.py` 挂载 `versions.router`）：
  - `POST /api/paperlab/questions/collect {qid}`：只读题库读取（与题库详情同一投影）→ 固定当时版本写入
    `pl_questions`（`status=draft`、`verify_status=pending`、私有）→ 同事务写 `origin=collect` 版本行；同名
    题重复收录返回 `already_collected:true`（不覆盖、不重复建题）；题库配图只提示不复制（`warnings`）。
  - `GET /api/paperlab/questions/{id}/versions`：版本历史（含 `content/is_current/content_sha256/asset_refs/
    source_*`），老数据首次读取补一条 `origin=snapshot` 当前版本（只追加）。
  - `GET /api/paperlab/questions/{id}/source-status`：`source_available/source_restricted/has_new_version/
    collected_* / current_* / diff:{changed,field_count,stem_similarity}/local_edited/notice/warnings`；
    来源下架/受限时不拉取、不回显受限正文。
  - `POST /api/paperlab/questions/{id}/update-from-source {confirm:true, expected_version?}`：显式确认后用题库
    新版生成 `version+1` 新版本并写 `origin=source_update` 版本行；未确认 422、版本冲突 409、非题库收录题 422、
    已最新 `updated:false`；历史版本与旧练习继续绑定旧内容。
- 列表/详情批量标注 `has_new_version/source_available`（一次只读探针，不逐题请求；`None` 表示题库暂不可读）。
- 前端 [`web/js/pages/mybank.js`](../web/js/pages/mybank.js)：来源/版本面板、`has_new_version` 徽标、
  差异字段与显式「收录新版」确认；投稿台 [`web/js/pages/submission.js`](../web/js/pages/submission.js) 从个人题
  创建投稿快照（Phase 2 链路）。

### 2.4 首页统计口径（`app/home_stats.py` + `GET /api/insight/home`）

- 新增 [`app/home_stats.py`](../app/home_stats.py)：`build_home(user_id, days)` → `{generated_at, range, bank,
  personal, caliber}`。
  - `bank`：复用 practice 的 `_answer_leak_sql/_excluded_sql/_bank_group_join` 门禁统计「可练（practice）」、
    「可自动判分（practice+auto 再扣题组材料缺失/答案缺失/数据质量标记）」、「待核验（可见题中不能自动判分）」，
    被门禁排除的题单独在 `excluded_by_gates` 与 `gates`；带 `bank_version/bank_source`，按题库文件 mtime/大小 +
    临时隔离集合缓存，题库异常时降级 `available:false` 不影响个人统计。
  - `personal`：`due_reviews`（错题本未归档且已到期）、`today{practice,classroom,paper,total}`（UTC 自然日，
    课堂小测与已提交整卷各计一次）、`first_attempt{samples,correct,accuracy}`（每题第一次已判定作答）、
    `repeat_practice{questions,attempts}`、`pending_grading{questions,attempts}`（最近一次仍 pending）、
    `library{questions,pending_review,drafts}`、`continue{last_attempt,last_paper}`、`weak_knowledge[]`
    （复用 insight 知识点口径，<70% 为薄弱，已判定样本 <3 标 `sample_limited`）、`knowledge_coverage`。
  - `caliber`：每项口径中文说明，前端直接展示，不复制数字。
- `GET /api/insight/home`（[`app/insight.py`](../app/insight.py) 注册，`?days=1-3650，默认 90`，`current_user`）：
  首页 [`web/js/pages/home.js`](../web/js/pages/home.js) 与学情页 [`web/js/pages/insight.js`](../web/js/pages/insight.js)
  并行读取，首页/学情同一后端口径；接口失败时保留既有空态/降级，不本地估算。

- [`web/js/main.js`](../web/js/main.js)：侧栏按组渲染；`admin` 按角色、`review`/`plaza-admin` 按

## 3. Phase 2 后端（`app/plaza/**`，25 条）

### 3.1 模块与数据层

- [`app/plaza/__init__.py`](../app/plaza/__init__.py)：`APIRouter(prefix="/api/plaza")`，固定路径先注册
  （`/me`、`/questions`、`/submissions/mine`）避免被 `{id}` 抢占；子模块 `roles/public/submissions/review/
  release/admin`。
- [`app/plaza/db.py`](../app/plaza/db.py)：8 张表幂等建表（按应用库身份做进程内去重；PostgreSQL 由
  `db._Postgres` 翻译 `?`→`%s` 与 `id INTEGER PRIMARY KEY`→identity）；写事务统一
  `write_lock(con,"plaza-write")` + `next_id/insert_row` 显式主键（不依赖 `lastrowid`/`RETURNING`）；
  `record_event` 与状态更新同事务；状态/阈值/可见性/角色/身份/媒体白名单等常量集中定义；
  `new_public_id()` = `plz-` + 20 位 hex（不可猜、与内部 id 解耦）。
- 表：`plaza_submissions`（投稿主表 + 当前快照/`fingerprint`/`license_confirmed`/`public_id`/评审截止）、
  `plaza_submission_versions`（逐版本留档）、`plaza_reviews`（`UNIQUE(submission_id,version,reviewer_id)`）、
  `plaza_releases`（发布指针 + 历史，`active_public_id` 唯一）、`plaza_events`（全链路事件）、
  `plaza_public_assets`（公开衍生图映射）、`plaza_roles`（角色/学科/到期/授权人，撤销置 `active=0`）、
  `plaza_identity`（身份申请，行保留供到期复核）。
- [`app/plaza/service.py`](../app/plaza/service.py)：不可变快照（内容白名单投影、配图只收资产引用）、
  来源/授权声明校验（`url/original_author/license_basis/rights_scope/attribution/reference/page_no/
  question_no` 公开 + `note` 内部）、`snapshot_checks`/`blocking_checks`、`review_summary` 独立票口径与阈值、
  按视角序列化（作者/评审/编辑/陌生人）、公开投影（不输出内部身份与存储路径）、权限依赖
  `require_plaza_role/require_editor/require_reviewer`（admin 直通）。
- [`app/plaza/figures.py`](../app/plaza/figures.py)：公开衍生图登记/授权/读取（见 §3.2）。
- [`app/auth.py`](../app/auth.py) 新增 `optional_user`：无/过期/损坏会话返 `None` 不抛 401，会话存储异常也按
  匿名处理；`current_user` 的 401 语义不变。

### 3.2 公开只读（4 条）

`GET /api/plaza/questions`（筛选/分页，仅 `community_review/verified/published` 且有 `public_id`）、
`GET /api/plaza/questions/{public_id}`（题面/答案/解析/知识点/来源声明/评审进度/`figure_notice`；
`withdrawn`/`disputed` 返回 200 + `visible:false` 状态页，不回显受限正文）、
`GET /api/plaza/assets/{asset_id}`、`GET /api/plaza/questions/{public_id}/images/{index}`
（只服务「公开稿件当前版本 + `public_derivative` 公开副本」，失败 404、非 png/jpeg/webp 415、
`Cache-Control: no-store`；不泄露存储路径/他人私有资产）。前两条用 `optional_user`（`GET /me` 同用
`optional_user`，见 §3.6），后两条公开图接口无登录依赖。

### 3.3 作者端投稿（7 条）

`POST /submissions`（从本人个人题生成不可变快照草稿，返回 preview + 逐项 checks）、`GET /submissions/mine`、
`GET /submissions/{id}`（按视角裁剪：评审员自己的票提交前隐藏他人投票、作者不含他人独立作答、编辑/管理员
可见审计字段）、`PATCH /submissions/{id}`（仅草稿；内容/来源/授权实质变化才建新版本）、
`POST /submissions/{id}/submit`（校验预览确认 + 阻断项，转 `pending_initial`）、
`POST /submissions/{id}/revise`（新版本从待评开始，旧票留档不计阈值）、
`POST /submissions/{id}/withdraw`（未发布前可撤；已发布须走发布端整条链）。全部 `current_user`，
他人投稿统一 404（作者端私有资源不泄露存在性）。

### 3.4 评审与阈值（4 条）

`POST /submissions/{id}/initial-review`（编辑初审来源/隐私/完整性；通过 → `community_review` + 公开题号 +
7 天窗口 + 公开图登记；拒绝需原因）、`GET /review/queue`（按学科授权分派、作者回避、已评版本不再出现、
投票隐藏）、`GET /review/mine`、`POST /submissions/{id}/reviews`（结构化评审 `approve/revise/reject/unsure`；
一人一版本一票；`revise/reject/unsure` 必填原因、`approve` 需独立作答/论证；冲突声明票不计独立票；
学科复核员 reject → `disputed`；阈值达成 → `verified`；响应含 `review_summary/transition`）。

### 3.5 签发 / 撤回 / 事件链（4 条）

`POST /submissions/{id}/publish`（编辑签发：回避本人投稿与本人复核题、要求阈值达成与授权确认、
已发布幂等 200；写 `plaza_releases(active)` + `published` 事件 + `public_url`）、
`POST /releases/{public_id}/withdraw`（normal/emergency；重复撤回幂等 200；发布指针与投稿状态同事务更新 +
`release_withdrawn` 事件；公开读取立即失效）、`GET /releases`（发布历史）、
`GET /submissions/{id}/events`（作者看节点、编辑/管理员看完整审计、评审员 403）。

### 3.6 角色 / 身份 / 编辑台（6 条）

`GET /me`（匿名 200 `authenticated:false`；登录返回 roles/identity/capabilities/stats）、
`POST /identity/apply`（身份类型/证明；同 kind+subject 待审幂等 200；身份仅展示，不参与权限）、
`POST /admin/roles`（管理员授权/撤销评审/学科复核/编辑，评审角色必须带学科、可设到期；撤销置 `active=0`
留档）、`GET /admin/submissions`（编辑台队列，作者脱敏 `投稿者·<sha256 前 6 位>`，默认待处理四状态，
状态可逗号多选）、`GET /admin/identity/queue`（pending/approved/rejected/expired/expiring/all）、
`POST /admin/identity/{id}/review`（approve/reject，驳回需原因，通过默认 365 天到期，写审计事件）。

### 3.7 审计、阈值与可见性摘要

- 状态机：`draft → pending_initial → community_review → verified → published`，分支
  `disputed/rejected/withdrawn/pending_release`；仅 `community_review` 可评、`verified|pending_release` 可签发。
- 阈值（`db.THRESHOLD_MIN_*`）：同版独立评审 ≥5、通过 ≥4、学科复核员通过 ≥2、无 reject 阻断 → `verified`；
  7 天未凑齐保持原状态（不自动通过/失败）。
- 回避：作者不评自己、编辑不初审自己、编辑不签发本人投稿或本人复核过的题；一人一版本一票由数据库唯一约束
  保证；冲突声明票留档不计票。
- 撤回传播：公开列表/详情/公开图授权以「稿件公开状态 + 当前版本 + 活跃 release」实时判定，公开图不缓存。
- 公开可见性：`community_review`（社区待核验，显著标注 + 评审进度）、`verified`、`published`（精选）；
  `disputed/withdrawn` 老链接返回 200 + 清晰状态，不静默 404。
- 事件链：`created/updated/submitted/revised/author_withdrawn/initial_review_accepted/
  initial_review_rejected/review_submitted/threshold_met/disputed/published/release_withdrawn/
  identity_approved/identity_rejected`，与状态更新同事务。

## 8. 风险与注意事项

1. **试点阈值是产品默认值**：≥5/≥4/≥2 与 7 天窗口集中定义在 `app/plaza/db.py`，需按试点供给与误判率调整；
   调整只改常量，不改变状态机。
2. **写锁与吞吐**：广场写事务统一 `db.write_lock(con,"plaza-write")` 串行化（SQLite 单写者；PostgreSQL 下
   为应用级 advisory 锁），高并发签发/评审时可能排队；如放量需按投稿/评审分锁或数据库约束替代。
3. **公开副本存储**：公开衍生图复制字节（≤20MB/张）会增加 `paperlab/assets` 体积与备份包体；撤回只停用
   映射、不删副本（审计需要），后续需回收策略。
4. **事件表增长**：`plaza_events` 只增；建议按季度归档/分区，并保留审计所需最小字段。
5. **公开图降级不阻断**：题库原始素材、未登记旧文件名、他人私有资产等配图不能公开时只提示
   `figure_notice`，不会阻断审核——访客看到的是「部分配图暂不可公开查看」，需运营侧知情。
6. **旧客户端/旧数据**：不带 `submission_id` 的作答仍非幂等；老个人题首次读取才补版本快照；广场无历史数据。
7. **真实环境联验缺口**：PostgreSQL 下 `plaza_*` 的显式主键/`write_lock`、并发投票与发布唯一约束未在真实
   实例联验；浏览器端访客壳/工作台交互仅有静态契约测试（`test_plaza_ui.py`/`test_plaza_workbench_ui.py`）。
8. **编号口径**：仓库既有《知序优化实施记录-20261121.md》标题为「第二轮」，本文件名按本轮任务口径为
   「第二轮」增量；两者是**先后承接关系**（本记录引用其为上一轮），对外引用时建议用日期+范围区分，
   避免仅凭「第 N 轮」误解轮次。
