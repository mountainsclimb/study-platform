报告 JSON（默认 `screenshots/accept-report.json`，可用 `-ReportPath` 指定）包含：

## 行为约定（本轮修复的“成功假象”）

- 只有**全部选中阶段真正执行且全过**（`skipped == 0`）才 `exit 0` / `ACCEPT OK`；
- 阶段失败、阶段异常、UI 模式服务器不可达 → `exit 1` / `ACCEPT FAILED`；
- 存在任何 SKIP（工具缺失、`-SkipPytest`、`-Stages` 过滤）→ `exit 3` / `ACCEPT INCOMPLETE`，
  汇总列出跳过阶段，**不再出现 `ACCEPT OK`**；没有阶段真正执行（空计划 / 全部跳过）同样 exit 3；
- 显式跳过与工具缺失（node/pnpm 未安装）记为 **SKIP**，不会被当成执行成功；
- 默认阶段：`bank → compileall → node-check → editor-typecheck → pytest`；`-Ui` 追加
  `ui-server → ui-routes → ui-upload → ui-modules`（`ui-upload` 为拍题入库页桌面/手机核对，整合模块端到端会先 `--seed`
  注入演示数据）；`-EditorBuild` 追加 `editor-build`（默认关闭，避免无 Node 环境无法验收）；
- 默认题库 = `releases/CURRENT` 指向版本；不读环境变量 `STUDY_BANK_DIR`，避免残留环境变量把验收悄悄切到 r3。
