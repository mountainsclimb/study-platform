## 1. 构建产物与脚本

- `scripts/build_markmap_bundle.mjs`：markmap 的 npm 包没有自包含浏览器产物
  （入口依赖 d3 与 markmap-common），脚本在开发机做一次性打包——临时目录安装
  锁定版本（markmap-view 0.18.13、markmap-common 0.18.9、d3 7.9.2、
  @babel/runtime 7.29.15；esbuild 0.28.2 仅构建期），esbuild 打成单 IIFE
  （`globalName: Markmap`，`legalComments: none`），写出产物 + 聚合 LICENSE +
  README（大小/SHA-256 登记）；`--check` 重建并逐字节比对磁盘产物。
- `web/vendor/markmap/`：`markmap-view.iife.min.js`（120,134 字节，SHA-256
  `cd44f6fb…4366095`）、`LICENSE`（按 esbuild metafile 实际打入的 33 个包逐包聚合，
  28,181 字节，SHA-256 `3f92393b…1f1df7`）、`README.md`。`--check` 实测**重建字节一致**。
- `scripts/markmap-bundle/package.json` + `package-lock.json`：顶层与全部传递依赖
  （d3 的 30 个子包等）钉死，构建改用 `npm ci`；实际打入的 33 个包为 markmap-view、
  markmap-common、d3 及 30 个 d3-* 子包（`@babel/runtime` 仅安装、未进入产物）。
- 样式经 markmap 的 `embedGlobalCSS` 内嵌在 SVG 内，无需外部 CSS 文件。

## 2. 接入点（`web/js/components/mindmap.js`）

- `loadMarkmap()`：懒注入 `/static/vendor/markmap/markmap-view.iife.min.js`
  （IIFE 全局 `Markmap`），15s 超时、失败可重试、中文降级。
- `renderInteractiveMindmap(tree, {title})`：把既有 `{label, children}` 树转成
  markmap 的 `{content, children}` 节点（**实测**：0.18 的渲染要求 `content`
  字段——官方流水线由 Transformer 生成，我们不引入 markmap-lib/transform，
  由组件自行转换）；`Markmap.create(svg, deriveOptions({maxWidth: 260}), data)`，
  `fit()` 按首帧后再调（初始渲染是异步过渡）；返回 `{element, destroy}`，
  `destroy()` 经 `instance.destroy()` 释放。
- 已知边界（实测记录，vendor README 的「已知边界」节同此说明）：
  - `initialExpandLevel` 不能作为选项传入（0.18 的 deriveOptions 白名单处理会崩，
    默认本就是 -1 全展开）；
  - options 必须直接用 `deriveOptions(...)` 的结果，不能作为 `style:` 二次嵌套。

## 3. 笔记页（`web/js/pages/notes.js`）

- 「思维导图」按钮打开时默认**静态**视图（现状不变），脑图区顶部出现
  「静态 / 交互」切换（`role="group"` + `aria-pressed`）。
- 切到交互视图懒加载构建产物；关闭脑图或再切换时销毁交互实例。
- `.mmd` 导出、静态 SVG 下载与既有 `renderMindmapWidget` 不受影响。
